# Fallible key generation in 0.4

The deprecated `crypto_x25519::generate_x25519_keypair` and
`crypto_secp256k1::generate_secp256k1_keypair` names now return
`Result<(Vec<u8>, Zeroizing<Vec<u8>>), CryptoError>`. They delegate to their
existing `try_generate_*` counterparts. Callers handle the result with `?` or
an explicit match; an unavailable OS entropy provider returns the canonical
`PROVIDER_RANDOMNESS_UNAVAILABLE` reason instead of entering the historical
infallible provider path.

Successful key generation keeps the same scalar generation, public-key
encoding and private-key cleanup ownership. The `try_generate_*` entry points
remain the preferred API. This deliberate 0.4 return-type change does not alter
published 0.3 packages or tags, and it does not change signature, key-agreement,
FFI, provider-selection or default-feature policy.
